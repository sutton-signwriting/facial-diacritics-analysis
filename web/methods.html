This exploratory browser compares existing SignPuddle signboxes with filtered facial compositions and provisional official Unicode sequences. It provides inspectable records for further analysis.

1. Source snapshot

The initial snapshot downloads every filename matching ^sgn[0-9]+\.spml$ from the HTTP SignPuddle directory listing. Original bytes are retained locally. A machine-readable manifest records source URLs, retrieval times, sizes, SHA-256 hashes, mapping profile, and font provenance.

The processor treats every file in its source directory as UTF-8 text and uses regular expressions. It accepts arbitrary filenames, including input.txt; no XML parser is involved. In SPML, this includes signboxes in entry terms, written passages, and other text fields. Every eligible occurrence is retained, including repeats. Counts describe this snapshot, not independent writers or representative community frequencies.

2. Three views, three fields

CSV columnDefinition
fswThe original spatial signbox, with its temporal prefix omitted. Symbol order and coordinates remain unchanged.
fsw-facePositioned resources in the spatial range query QR2fft36c, excluding all fills and rotations of bases S337, S338, S339, and S33a. These air and breath symbols map to U+1DA37–U+1DA3A and are not facial diacritics. Other resources and the temporal prefix are removed. Glyph-aware normalization uses only the retained symbols, translates the composition to a center of 500,500, and recomputes its maximum extent.
uni-faceA provisional sequence of official Unicode SignWriting characters. The first existing S2ff resource, together with its modifiers, moves to the front. If none exists, U+1D9FF HEAD is prepended. Remaining resources retain source order.

The primary facial dataset includes only faces containing at least two retained non-S2ff resources, counted after removing the air and breath symbols. Zero-diacritic and single-diacritic faces are excluded; HEADs and fill/rotation modifiers do not count toward this threshold. Additional S2ff HEAD resources remain present and are flagged. The flag counts explicit S2ff resources, not visually separate faces. A prepended HEAD means no S2ff resource was found; other source resources may already contain a head outline. Original fsw signboxes preserve the excluded symbols. A failed normalization is recorded in the processing report with its source location; it is not silently converted. The primary dataset CSVs have exactly the three columns above. Per-row provenance includes the source occurrence, character offset, complete matched FSW including any temporal prefix, entry ID when available, and mapping flags.

Separate analysis of eye gaze with fills 2 and 3

The eye-gaze listing scans the original source files independently. It selects every signbox with at least one positioned symbol from S321 through S329 whose fill is 2 or 3, at any rotation, matching S32[1-9][23][0-9a-f]. Fills 0 and 1 are excluded as qualifying gaze matches. A gaze appearing only in a temporal prefix does not qualify. There is no minimum diacritic count. Original signboxes, repeats, and source provenance remain available; private collections remain excluded.

Signs containing both fill-2/3 gaze and other gaze fills are included and flagged. The Gaze fills filter can restrict the view to signs using only fills 2 and 3 or to mixed-fill signs. Each match lists its original symbol key and source coordinates. Selection does not infer a left or right eye association.

Facial context and the provisional Unicode view follow the same extraction and mapping rules as the primary analysis, including the S337–S33a exclusions. A normalization failure does not remove a matching sign: its source is retained and the unavailable view is identified. Unknown source gaze variants are retained with a diagnostic flag.

The separate manifest records the selection and counts. The combined CSV and individual eye-gaze CSVs add source filename, entry ID, character offset, matching gaze keys, and original gaze coordinates after the three shared rendering fields. These files are separate from the primary dataset.

3. The provisional Unicode mapping

For a symbol Sbbbf r (spaces added for explanation), the official base code point is 0x1D700 + bbb. Nonzero fills add 0x1DA9A + f; nonzero rotations add 0x1DAA0 + r. Fill 0 and rotation 0 are inherent and produce no explicit modifier. Modifiers remain attached to their source resources. These are official block code points, not the SWU representation.

This first mapping transfers symbol categories and source ordering. It does not transfer coordinates, decompose head-bearing ISWA resources, resolve multiple-head associations, choose a linguistic reading, or establish faithful reconstruction. The “number of diacritics” filter counts retained non-S2ff resources, not fill/rotation code points. Air and breath resources S337–S33a are absent from both filtered views.

Compare the Unicode facial model in §21.7 with the source specifications before interpreting a display. A plausible rendering is not a demonstrated preservation result.

Reading a display difference

A source signbox can contain several separately positioned heads or faces. The direct mapping retains additional S2ff characters but does not segment the source into faces or assign each mark to its spatial head. Multiple visible faces can therefore be merged or otherwise misassociated in the Unicode view. The S2ff count alone does not detect every such composition.

The mapping also keeps source fills and rotations; it does not search alternative fills or face constructions. A different selection might allow Noto to reproduce a desired arrangement, but equivalence to the source would need to be checked. The browser has not classified differences as mapping limitations, unavailable font behavior, or information missing from the facial sequence. Alternative constructions would belong to a separately named mapping profile, with the original records retained.

4. Rendering and normalization

Original and filtered signboxes use the bundled @sutton-signwriting/font-ttf 1.6.0 library and Sutton fonts. Normalization uses the 37,811-entry ISWA size table, with symbol extents included, and a single integer translation. Relative coordinates and overlap order are retained. Each FSW rendering is fitted independently to its table cell.

The dataset uses the pinned size table for canonical normalization. The browser library measures glyph bounds on a live canvas and can obtain slightly different metrics. Verification checks the stored geometry against the pinned table and records the independent library comparison separately. These metric diagnostics are not assessments of facial equivalence.

Unicode uses the bundled Noto Sans SignWriting font in the visitor’s browser, left to right, with default shaping features. The exact Noto binary is identified by URL and SHA-256 in the manifest. Browser shaping can differ across systems; this display does not reproduce or validate the earlier ten-pair Noto diagnostic. Font licenses accompany the assets.
